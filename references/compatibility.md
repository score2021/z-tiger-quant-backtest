# 兼容排查

经验来自 2026-10-17 的一次实际排错，可能随账户和版本变化，不是完整黑名单。

| 现象 | 实测证据 | 处理 |
| --- | --- | --- |
| `NotAllowException: code contains dangerous word: os` | 无害属性 `context.costs` 和提示文字 `Possible` 曾触发，改写后通过 | 定位代码/字符串；记账字段可改为 `fees`，提示文字改写。不要机械替换官方 `close`，不要编码或动态执行绕过限制 |
| `dangerous word: exec` | 普通日志中的 `execution` 曾触发，改为 `fills` 后编译通过 | 检查提示文本而不只检查导入；只改写无害说明文字，不执行或混淆被禁功能 |
| `Wrong first trading day: 2018-07-02` | UI 为 2018 年下半年，代码固定要求 2016-01-04 | 将短测代码起止与 UI 一起调整，或恢复原定 UI 区间；保留真实起点校验 |
| `超过杠杆，浮动杠杆默认限制为4倍` | 原生代码设为 1 倍仍出现该固定文字；订单实际延后成交 | 提示中的“4倍”不能代替读取配置。检查成交价、现金和挂单；无融资场景按[现金约束](execution.md)修复，不直接改成 4 倍 |
| `name 'sorted' is not defined` | 年度统计运行到该函数时报错 | `ordered = list(values)`，再 `ordered.sort()`；其他内置函数先验证 |
| “服务器运行出错” | 拆开条件、改写部分表达式后逐步通过，无内部堆栈 | 保存失败版本，从最小程序二分恢复。不要断言所有 `or`、`all`、二维索引永久禁用；多处同时修改不能证明单一原因 |
| 午夜日线被“15 点前禁止”拦截 | 每日模式回调实际为 `00:00:00` | UI 选每日，移除不适用的小时断言；日期去重不替代频率设置 |
| 快速区为空或长任务显示异常 | 长任务曾在历史列表成功，完整日志可下载 | 核对“历史回测结果”的任务时间、参数和日志，不盲目重跑 |

## 行情接口

[官方文档](https://quant.itiger.com/tquant/docs/zh-cn/docs/data/quote.html)：单 asset、单字段 history 返回 Series；单 asset、多字段 history 返回 DataFrame；单 asset、多字段 current 返回字段索引的 Series。

```python
history = data.history(asset, "close", 252, "1d")
current = data.current(asset, ["open", "close"])
```

先用单标的单字段验证。历史接口描述为回测日前的 K 线，仍需检查实际索引，确保信号使用已完成日线。检查价格有限且大于零、窗口足量、最后历史时间戳早于今日、多个标的日历一致。按需读取，避免反复拉取不需要的历史。

## 预热与起点

本次观察：2014-01-03 的当日价格可读，但历史读取返回空数组/长度错误；2015-01-02、2016-01-04 能读取此前 252 根收盘。不能由此断言所有资产/账户数据都始于 2014。

不要用初始化日期推断首次交易回调日期：已观察到二者同日或不同日。周末开始的 2018-07-01 测试首个回调为 2018-07-02；后续原生测试记录初始化和正式回调均为 2016-01-04。不能一律要求 UI 提前一日，也不能把自然日当交易日。既有比较 UI 从 2014-01-02 起，正式比较从 2016-01-04 起；这不叫“2014 起的策略收益”。以实际回调和足量历史核验。

252 日不足不能改为 `min(252, available)` 后仍称同策略。增加预热、明确推迟共同起点或报告无法满足；改起点后对齐所有策略。

## 企业行为与统计

确认历史与当日价格复权、现金分红口径。历史重算时，保存的前高、入场前高、移动峰值、再入场锁价也需同口径处理；用已知拆分/分红事件验证，不凭价格倍数猜测修补。

TQQQ 收益不严格等于 QQQ 三倍。大偏差可提示调查，但不能证明拆分；小偏差也不能证明数据完全正确。不要用合成 `3*r` 冒充真实 ETF 行情。

## 完成证据

核对代码版本、UI 日期/频率/资金、实际正式首末日、日数、全部账本有效结果、终点标记及未被静默跳过的异常。完成标记应只在所有账本到达终点后打印。平台“成功”与完整日志互证。

失败案例中下载的 `.log` 只有 INFO 记录，异常另显示在网页底部。日志中止在某日不等于那日就是报错日。滚到页面底部或查看“错误”区读取原文，再定位；不要根据最后一条普通信号猜异常。原生订单验收见[成交与现金约束](execution.md)。

用户要求 computer use 时用当前支持的 UI 工具执行。Chrome 全屏、窗口焦点和连接超时属于本机问题，不写成所有用户必须遵守的固定步骤。
