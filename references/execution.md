# 原生成交与现金约束

编写带订单的策略时先读本页。官方接口：[下单](https://quant.itiger.com/tquant/docs/zh-cn/docs/order/order.html)、[订单查询与撤单](https://quant.itiger.com/tquant/docs/zh-cn/docs/order/other_order.html)、[对象](https://quant.itiger.com/tquant/docs/zh-cn/docs/obj.html)、[费用与杠杆](https://quant.itiger.com/tquant/docs/zh-cn/docs/init.html)。接口与行为可能变化，使用前核对。

## 本次发现及边界

- 原代码用当日开盘价估算股数，再提交市价订单；日志显示后续交易日才成交。完整失败页面显示“超过杠杆，浮动杠杆默认限制为4倍”，代码配置却是 `set_max_leverage(1.0)`。延后成交导致现金预算失效是待排查的具体机制，不凭报错文字推断真实杠杆数值或精确超限金额。
- 修正版保留 1 倍账户杠杆限制：先确认卖出成交，再使用到账现金提交受限价约束的买单；保留费用现金，跟踪撤单。该案例完整区间已通过，见[验证记录](validation.md)。不能据此断言所有市价单都在某固定时点成交。
- 限价未成交及分阶段调仓会造成延迟和低配。该改变属于执行模型变化，不能称与“次日开盘、固定6bps、分数股”的虚拟账本完全等价。目标仓位与实际持仓分开报告。

## 现金不变量

无融资策略应满足：

`新买单的股数 × 各自最高成交限价之和 ≤ 已到账可用现金 − 费用及现金预留`

只比较目标权重之和不超过 100% 不足以证明不会透支；未成交卖单的预计回款不算到账现金。没有已验证的资金冻结语义时，先处理已有挂单再计算新预算。卖单数量不得超过实际持仓，先卖后买不能仅理解为把两个调用顺序交换。

参考[样例](../examples/cash-orders.py)的分阶段方案。样例中 0.5% 预留、最低20美元、买价上限为参考价的1.01倍来自本次配置，**不是通用最优值或费用保证**；按标的、账户费用和用户要求调整。若用户要求市价成交模型，另行验证保守规模与现金限制；不要暗中改成限价，也不要放松融资限制。

整数股向下取整并扣除费用空间。多只买单共享同一预算，不能每笔各自花满账户现金。设置费用模型须有真实 API 支持；本次官方文档注明 `set_commission` 尚未实现，原生费用使用平台默认模型，不能伪装成自定义比例费用。

## 订单生命周期

本次官方状态码：`5=open`、`9=partial filled`、`6=filled`、`4=cancelled`、`8=rejected`。

- 5/9 不代表策略计算失败；记录已成交数量与剩余挂单，对过期单申请撤单或继续等待，按策略声明选择。
- `cancel_order` 是异步操作。撤单请求不是终态，ID 应保留，确认4或6后再释放跟踪并重新计算预算，防止重复买入。撤单过程中发生全成也按6处理。
- 8、订单缺失、未知状态应带订单ID和原因报错，不能静默清空后继续报成功。
- 持仓以平台实际持仓为准，不用信号状态冒充成交状态。若异步交易只让执行层等待，信号仍需按声明的日历更新；若选择冻结信号，则这是规则变化，需说明。

## 日期与完成判据

固定研究起点时，UI 和 `TRADE_START` 的首个实际交易日必须匹配。短测也同时调整 `TRADE_END`；不要一边跑2018年，一边保留2016年固定首日断言。若允许“自动使用界面首个有效交易日”，显式提供该模式，输出实际起点，不冒充固定区间结果。

不能假定初始化消耗首个交易日。区分自然日与交易日，记录初始化和首个回调，用交易日历或短测核实。

终点输出至少包含实际首末日、处理日数、未终结订单。`SIGNALS_COMPLETE` 只表示信号处理到终点。若终点仍挂单或有未核对异常，不写“全部成交完成”。原生例子为避免末日提交无法在区间内成交的订单，末日仅估值、不新下单；采用此约定时在交付中说明，并检查上一日挂单。
